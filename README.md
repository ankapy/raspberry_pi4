# Raspberry Pi 4: настройка и эксплуатация

Стартовая настройка для Raspberry Pi OS / Debian 13 (trixie), arm64.

Эталонная среда:
- Raspberry Pi 4 Model B Rev 1.5, 4 GB
- ОС: Debian GNU/Linux 13 (trixie), ядро rpt-rpi-v8, arm64
- Хост: psybot, пользователь: crashkkm
- Сеть: Ethernet, статический адрес 192.168.0.103
- Охлаждение: корпус с вентилятором, подключенным к 5V/GND (постоянно включен)
- Резервные копии: USB-флешка 64 ГБ (exFAT), точка монтирования /mnt/usb-backup, архивы tar.gz раз в неделю, хранение 30 дней

## 1. Первый запуск и базовая конфигурация

```bash
# Интерактивный мастер начальной настройки: локаль, часовой пояс, hostname.
sudo raspi-config

# Установить часовой пояс без мастера.
# Когда: один раз при настройке, если часовой пояс не задан.
sudo timedatectl set-timezone Europe/Moscow

# Задать имя устройства в сети (hostname).
# Когда: один раз, если хотите осмысленное имя вместо raspberrypi.
sudo hostnamectl set-hostname psybot

# Мастер настройки сети (в т.ч. статического адреса) с текстовым интерфейсом.
# Рекомендуется вместо этого зарезервировать IP по MAC-адресу на роутере.
sudo nmtui

# Проверка результатов.
timedatectl    # покажет Time zone: Europe/Moscow
hostnamectl    # покажет Static hostname: psybot
ip -br a       # краткий список сетевых интерфейсов и их IP-адресов
```

Пояснение к `ip -br a`: выводит по одной строке на интерфейс.
`eth0 UP 192.168.0.103/24` означает: проводная сеть работает, адрес 192.168.0.103.

## 2. Обновление системы

```bash
# Скачать свежие списки доступных пакетов из репозиториев.
# Сама система при этом НЕ обновляется, обновляются только списки.
sudo apt update

# Установить все доступные обновления, включая ядро и firmware Raspberry Pi.
# Флаг -y означает "отвечать да на все вопросы".
# Если спросит про измененные конфигурационные файлы и вы их не правили -
# выбирайте установку версии из пакета (maintainer's version).
sudo apt full-upgrade -y

# Удалить пакеты-сироты, которые больше не нужны после обновлений.
# --purge дополнительно удаляет их конфигурационные файлы.
sudo apt autoremove -y --purge

# Очистить кэш скачанных установочных файлов, освобождает место на SD-карте.
sudo apt clean

# Обязательно выполнить, если обновлялись ядро или firmware:
# изменения ядра применяются только после перезагрузки.
sudo reboot
```

Когда запускать: сразу после установки ОС и далее примерно раз в 1-2 недели.

## 3. Базовые пакеты

Одной командой ставится набор повседневных утилит:

```bash
sudo apt install -y \
  git curl wget rsync unzip \
  htop tmux ncdu jq \
  vim nano \
  python3-venv python3-pip \
  build-essential \
  bash-completion \
  ufw fail2ban unattended-upgrades
```

Назначение пакетов:
- git - система контроля версий, клонирование репозиториев с GitHub;
- curl, wget - загрузка файлов и HTTP-запросы из терминала;
- rsync - надежное копирование файлов и папок, в т.ч. на другие машины;
- unzip - распаковка zip-архивов;
- htop - наглядный монитор процессов и нагрузки (выход - клавиша q);
- tmux - "виртуальные терминалы": сессия не обрывается при разрыве SSH;
- ncdu - интерактивный анализ занятого места на диске (выход - q);
- jq - удобный просмотр JSON-ответов API;
- vim, nano - текстовые редакторы (новичку - nano);
- python3-venv, python3-pip - виртуальные окружения и менеджер пакетов Python;
- build-essential - компиляторы и библиотеки для сборки пакетов;
- bash-completion - автодополнение команд по Tab;
- ufw - простой межсетевой экран (файрвол);
- fail2ban - автоматическая блокировка IP после серии неудачных входов;
- unattended-upgrades - автоматическая установка обновлений безопасности.

Когда запускать: один раз после обновлений системы.

## 4. Docker

Docker - платформа контейнеров: изолированных "коробок" с приложением и его
зависимостями. Контейнер не ломает систему, легко удаляется и перезапускается.
Это основной способ размещения ботов и сайтов на данной машине.

```bash
# Скачать официальный установочный скрипт Docker в текущую папку.
curl -fsSL https://get.docker.com -o get-docker.sh

# Запустить его. Флаги: -f стоп при ошибке, -s тихий режим, -L следовать редиректам.
# Скрипт сам добавит репозиторий Docker и установит все компоненты.
sudo sh get-docker.sh

# Удалить установочный скрипт, он больше не нужен.
rm get-docker.sh

# Добавить текущего пользователя в группу docker.
# Зачем: чтобы запускать docker без sudo.
# $USER - переменная с именем текущего пользователя, подставлять ничего не нужно.
sudo usermod -aG docker "$USER"

# Применить новую группу в текущей сессии без переподключения.
# Альтернатива: просто завершить SSH-сессию и подключиться заново.
newgrp docker

# Включить автозапуск Docker при загрузке ОС.
sudo systemctl enable docker
```

Проверка:

```bash
docker --version          # покажет версию Docker, например Docker version 27.x
docker compose version    # покажет версию Compose, например v2.x
docker run --rm hello-world
```

Пояснение к последней команде:
- `docker run` - скачать и запустить контейнер с указанным образом;
- `--rm` - удалить контейнер сразу после завершения работы;
- `hello-world` - тестовый образ, выводящий приветственное сообщение.
Ожидается текст "Hello from Docker!" - значит Docker работает корректно.

Правило для своих сервисов: в compose-файлах всегда указывать
`restart: unless-stopped`, чтобы контейнеры сами поднимались после перезагрузки.

## 5. Веб-стек: Nginx + Certbot

Nginx - веб-сервер. В нашей схеме он работает как reverse proxy: принимает все
запросы из интернета на портах 80/443 и передает их внутрь нужного контейнера.
Certbot - утилита бесплатных SSL-сертификатов Let's Encrypt (сайт по https).

```bash
# Установить nginx, certbot и плагин интеграции certbot с nginx.
sudo apt install -y nginx certbot python3-certbot-nginx

# Включить автозапуск nginx и запустить его сейчас.
sudo systemctl enable --now nginx

# Выпустить сертификат для домена и автоматически прописать его в конфиг nginx.
# -d example.com - основной домен, второй -d www.example.com - алиас.
# Домен должен быть заранее направлен на публичный IP сервера.
# Запускать один раз на сайт, повторно - только для добавления доменов.
sudo certbot --nginx -d example.com -d www.example.com

# Проверить, что автопродление сертификата запланировано таймером.
# systemctl list-timers выводит список таймеров, grep отбирает строки со словом certbot.
# Символ | называется pipe: вывод первой команды подается на вход второй.
systemctl list-timers | grep certbot
```

Конфиг сайта-прокси, файл `/etc/nginx/sites-available/app`
(создать через `sudo nano /etc/nginx/sites-available/app`):

```nginx
server {
    server_name example.com;          # домен, который обслуживает этот блок

    location / {                      # правило для всех адресов сайта
        proxy_pass http://127.0.0.1:8000;   # куда перенаправлять: порт контейнера
        proxy_set_header Host $host;                 # передать исходный домен
        proxy_set_header X-Real-IP $remote_addr;     # передать реальный IP клиента
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;  # передать факт https
    }
}
```

```bash
# Включить сайт: создать символическую ссылку из sites-enabled на наш файл.
# nginx читает только то, что лежит в sites-enabled.
sudo ln -s /etc/nginx/sites-available/app /etc/nginx/sites-enabled/

# Проверить синтаксис конфигов и, если ошибок нет, перечитать их без простоя.
# nginx -t - тест конфигурации; reload - мягкая перезагрузка без разрыва соединений.
sudo nginx -t && sudo systemctl reload nginx
```

Пояснение к `&&`: вторая команда выполнится только если первая завершилась успешно.

## 6. Среды выполнения для ботов

### Python (основной вариант)

```bash
# Создать папку для ботов и перейти в нее.
mkdir -p ~/bots && cd ~/bots

# Создать виртуальное окружение venv: изолированную область для Python-пакетов,
# чтобы зависимости разных ботов не конфликтовали между собой.
python3 -m venv venv

# Активировать окружение в текущей сессии терминала.
# После этого в приглашении появится приставка (venv).
source venv/bin/activate

# Обновить установщик пакетов и поставить библиотеки бота.
pip install --upgrade pip
pip install python-telegram-bot requests

# Выйти из виртуального окружения, когда работа закончена.
deactivate
```

Когда запускать: venv создается один раз; pip install - при добавлении библиотек.
Важно: перед запуском бота вручную окружение нужно активировать командой source.
Если бот работает в Docker, venv не нужен.

### Node.js (опционально)

```bash
# Добавить репозиторий NodeSource с актуальной LTS-версией Node.js 22.
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo bash -

# Установить nodejs из добавленного репозитория и проверить версию.
sudo apt install -y nodejs
node --version
```

### PM2 (только для процессов вне Docker)

```bash
# Менеджер процессов: держит бота запущенным, перезапускает при падении.
sudo npm install -g pm2
pm2 start bot.js --name tg-bot   # запустить скрипт под именем tg-bot
pm2 save                         # сохранить список процессов
pm2 startup                      # вывести команду автозапуска PM2, ее нужно выполнить
```

Рекомендация: боты и сайты держать в Docker с политикой restart, PM2 - только для legacy-скриптов.

## 7. Мониторинг: Netdata и температура

Netdata - агент мониторинга с веб-графиками: CPU, память, диск, сеть, температура.

```bash
# Скачать установочный скрипт Netdata во временный файл.
wget -O /tmp/kickstart.sh https://get.netdata.cloud/kickstart.sh

# Установить в неинтерактивном режиме (без вопросов в процессе).
sudo bash /tmp/kickstart.sh --non-interactive

# Убедиться, что служба работает: ожидается ответ active.
systemctl is-active netdata

# Быстрая проверка веб-части: вывести первые 200 символов служебного JSON.
# head -c 200 обрезает вывод до 200 символов, чтобы не засорять терминал.
curl -s http://127.0.0.1:19999/api/v1/info | head -c 200
```

- Дашборд открывается с любого ПК локальной сети: `http://192.168.0.103:19999`
- График температуры: строка поиска дашборда, слово `temperature`, раздел Sensors.
- Уведомления в Telegram настраиваются в файле
  `/etc/netdata/health_alarm_notify.conf`, после правки:
  `sudo systemctl restart netdata`

### Температура и троттлинг из консоли

```bash
vcgencmd measure_temp
```
- Что делает: утилита vcgencmd обращается к чипу VideoCore и читает датчик
  температуры процессора. measure_temp - команда "показать температуру".
- Пример вывода: `temp=45.2'C` - сейчас 45.2 градуса Цельсия.
- Когда запускать: разовая проверка в любой момент, особенно после нагрузок.

```bash
vcgencmd get_throttled
```
- Что делает: показывает флаги защитных механизмов платы
  (перегрев, нехватка питания, снижение частот).
- Пример вывода: `throttled=0x0`. Норма - именно 0x0, все флаги сброшены.
- Ненулевое значение означает проблему, расшифровка в разделе 13.
- Когда запускать: при подозрении на перегрев или нестабильность, планово раз в неделю.

```bash
watch -n 2 'vcgencmd measure_temp; vcgencmd get_throttled'
```
- Что делает: watch запускает указанную команду повторно каждые N секунд
  и перерисовывает экран, получается живой монитор.
- `-n 2` - интервал обновления 2 секунды.
- Кавычки обязательны: внутри них через точку с запятой перечислены ДВЕ команды,
  которые watch выполнит как одну связку. Без кавычек watch получил бы только первую.
- Выход из режима наблюдения: Ctrl+C.
- Когда запускать: во время стресс-теста, при проверке охлаждения,
  после установки нового вентилятора или корпуса.

Диапазоны температур Pi 4:

| Диапазон, C | Статус |
|---|---|
| 35-50 | Идеально, простой |
| 50-70 | Штатно под нагрузкой |
| 70-79 | Повышенная, проверить охлаждение |
| 80-85 | Троттлинг, падение производительности |
| > 85 | Опасный режим |

## 8. Автоматическая очистка диска

Настройка выполняется один раз сразу после установки базового софта.
Далее система сама будет ограничивать рост логов и удалять мусор по расписанию.
Это уменьшает износ SD-карты и делает резервные копии компактнее.

### 8.1 Ограничение размера логов Docker

По умолчанию логи контейнеров растут бесконечно. Ограничим их 30 МБ на контейнер.

```bash
# Создать каталог конфигурации Docker, если его еще нет.
sudo mkdir -p /etc/docker

# Записать настройки: драйвер json-file, максимум 3 файла по 10 МБ.
# Когда лог достигнет 10 МБ, он будет ротирован (создан новый файл).
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
EOF

# Перезапустить демон Docker, чтобы применить новые настройки.
sudo systemctl restart docker
```

- Что делает: файл `/etc/docker/daemon.json` читается при запуске демона.
- Когда запускать: один раз при первоначальной настройке.
- Ограничение применяется ко всем новым контейнерам. Уже созданные контейнеры
  продолжат использовать старые настройки до пересоздания.

### 8.2 Ограничение размера системных журналов (systemd journal)

Журнал systemd по умолчанию может занимать до 10% диска. Жестко ограничим его.

```bash
# Открыть конфиг в редакторе.
sudo nano /etc/systemd/journald.conf
```

В файле найти строки `SystemMaxUse=` и `MaxRetentionSec=`, убрать в начале `#`
и выставить значения:

```ini
SystemMaxUse=200M
MaxRetentionSec=7day
```

- `SystemMaxUse=200M` - журнал никогда не займет больше 200 МБ.
- `MaxRetentionSec=7day` - записи старше 7 дней удаляются автоматически.

```bash
# Перезапустить службу журнала.
sudo systemctl restart systemd-journald

# Принудительно удалить старые записи прямо сейчас.
sudo journalctl --vacuum-time=7d

# Проверить, сколько места занимает журнал.
journalctl --disk-usage
```

### 8.3 Ротация логов веб-сервера Nginx

Логи Nginx уже ротируются встроенной утилитой `logrotate`. Проверим, что конфиг
в порядке и при необходимости ужесточим хранение.

```bash
# Посмотреть текущий конфиг ротации nginx.
cat /etc/logrotate.d/nginx
```

По умолчанию: ротация еженедельно, хранение 14 недель. Если нужно сократить
до 4 недель, чтобы не занимать лишнее место на диске:

```bash
sudo nano /etc/logrotate.d/nginx
```

Найти строку `rotate 14` и заменить на `rotate 4`. Сохранить.
Далее logrotate сам отработает по своему таймеру, ничего запускать не нужно.

### 8.4 Автоматическая очистка через cron

Планировщик `cron` будет сам запускать очистку по расписанию.

```bash
# Открыть расписание суперпользователя.
sudo crontab -e
```

Добавить в конец файла следующие строки:

```cron
# Каждое воскресенье в 04:00 удалять неиспользуемые образы, контейнеры,
# сети и временные тома Docker. Флаг -af означает "удалить все без вопросов".
# --volumes удаляет тома, не привязанные ни к одному контейнеру.
0 4 * * 0 /usr/bin/docker system prune -af --volumes

# Первое число каждого месяца в 05:00:
# 1. apt autoremove --purge - удалить пакеты-сироты вместе с их конфигами;
# 2. apt clean - очистить кэш скачанных deb-файлов.
# && гарантирует, что clean выполнится только при успешном autoremove.
0 5 1 * * /usr/bin/apt autoremove --purge -y && /usr/bin/apt clean

# Каждый понедельник в 04:30 очищать пользовательский кэш pip во всех venv.
# find ищет все файлы *.whl и *.tar.gz в папке .cache/pip старше 30 дней.
30 4 * * 1 find /home -path '*/.cache/pip/*' \( -name '*.whl' -o -name '*.tar.gz' \) -mtime +30 -delete
```

- Что делает: cron запускает указанные команды в заданное время.
- Когда запускать: один раз при настройке, далее система работает сама.
- Формат строки: `минута час день_месяца месяц день_недели команда`.
- `*` означает "любое значение", `0` в дне недели - воскресенье, `1` - понедельник.

### 8.5 Очистка временной папки /tmp

Папка `/tmp` по умолчанию очищается при каждой перезагрузке. Поскольку сервер
работает долго без перезагрузки, настроим дополнительное удаление старых файлов.

```bash
# Создать файл правил очистки временных файлов.
sudo tee /etc/tmpfiles.d/custom-tmp.conf <<'EOF'
# Очищать файлы в /tmp, к которым не обращались более 7 дней.
# q - создать каталог, если его нет; 1777 - права; root root - владелец; 7d - возраст.
q /tmp 1777 root root 7d
EOF
```

- Что делает: `systemd-tmpfiles` при загрузке и по таймеру удалит старые файлы.
- Когда запускать: один раз, далее система работает сама.

### 8.6 Проверка результатов

Через неделю после настройки можно убедиться, что автоочистка работает:

```bash
# Посмотреть журнал cron: записи о выполненных задачах очистки.
sudo journalctl -u cron --since "7 days ago"

# Проверить, сколько места занимают ключевые каталоги.
```

## 9. Безопасность

### Вход по SSH-ключу вместо пароля

```bash
# ВЫПОЛНЯЕТСЯ НА РАБОЧЕМ ПК, не на Raspberry Pi.
# Создает пару ключей: закрытый остается на ПК, открытый копируется на сервер.
ssh-keygen -t ed25519

# Копирует открытый ключ на Raspberry Pi и разрешает вход без пароля.
ssh-copy-id crashkkm@192.168.0.103
```

```bash
# ВЫПОЛНЯЕТСЯ НА Raspberry Pi и ТОЛЬКО после того, как вы убедились,
# что вход по ключу работает: откройте НОВУЮ сессию ssh без пароля.
# sed -i правит файл на месте: находит строку PasswordAuthentication
# и заменяет ее значение на no, запрещая вход по паролю.
sudo sed -i 's/^#*PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config

# Применить измененный конфиг SSH.
sudo systemctl restart ssh
```

Предупреждение: если отключить пароли до проверки ключа, можно потерять доступ.
Текущую сессию не закрывайте, пока не проверите вход из нового окна.

### Межсетевой экран UFW

```bash
# Базовая политика: все входящие соединения запрещены...
sudo ufw default deny incoming
# ...все исходящие разрешены.
sudo ufw default allow outgoing

# Разрешить SSH, иначе после включения firewall вы не подключитесь.
sudo ufw allow 22/tcp

# Разрешить веб-трафик: 80 - http, 443 - https.
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# Разрешить Netdata ТОЛЬКО из локальной сети 192.168.0.x.
# Запись 192.168.0.0/24 означает "все адреса с 192.168.0.1 по 192.168.0.254".
sudo ufw allow from 192.168.0.0/24 to any port 19999 proto tcp

# Включить firewall. Спросит подтверждение - ответить y.
sudo ufw enable

# Показать итоговые правила и состояние: ожидается Status: active.
sudo ufw status verbose
```

Важно: Docker публикует порты контейнеров через собственные правила iptables
и игнорирует ufw. Не пробрасывайте порты контейнеров наружу без необходимости,
внешний вход должен идти только через nginx.

### fail2ban: защита от подбора пароля

```bash
# Создать файл локальных настроек fail2ban для SSH.
# Конструкция sudo tee файл <<'EOF' записывает в файл весь текст до строки EOF.
# Это удобный способ записать несколько строк одной командой.
sudo tee /etc/fail2ban/jail.d/sshd.local <<'EOF'
[sshd]
enabled = true     # включить наблюдение за SSH
maxretry = 5       # бан после 5 неудачных попыток входа
findtime = 10m     # попытки считаются за окно в 10 минут
bantime = 1h       # длительность блокировки IP - 1 час
EOF

# Включить автозапуск и запустить службу сейчас.
sudo systemctl enable --now fail2ban

# Показать статистику блокировок по SSH: список забаненных IP и счетчики.
sudo fail2ban-client status sshd
```

### Автообновления безопасности

```bash
# Файл периодических задач apt:
# первая строка - ежедневно обновлять списки пакетов,
# вторая - ежедневно автоматически ставить обновления безопасности.
sudo tee /etc/apt/apt.conf.d/20auto-upgrades <<'EOF'
APT::Periodic::Update-Package-Lists "1";
APT::Periodic::Unattended-Upgrade "1";
EOF
```

## 10. Резервное копирование на внешний USB-накопитель

Схема: раз в неделю система архивирует домашний каталог и /etc в tar.gz на
USB-флешку, подключенную постоянно. Архивы старше 30 дней удаляются автоматически.
Дополнительно перед рискованными изменениями делается локальный снимок на SD-карте.

Предупреждение: бэкап на флешке защищает от потери конфигурации и случайного
удаления, но не защищает от одновременного выхода флешки и SD-карты из строя
(например, при аварии питания). Раз в месяц копируйте свежий архив на ПК.

### 10.1 Одноразовая настройка флешки

Флешка отформатирована в exFAT на ПК (почему не ext4 средствами Pi - см. раздел 13).
На самой Pi выполняется только настройка монтирования.

```bash
# Найти флешку и имя ее раздела (обычно sda и sda1).
lsblk

# Узнать UUID раздела для fstab.
sudo blkid /dev/sda1

# Создать точку монтирования.
sudo mkdir -p /mnt/usb-backup

# Добавить автомонтирование в fstab, подставив UUID из blkid.
# nofail - при отсутствии флешки система загрузится без нее.
sudo nano /etc/fstab
```

Строка fstab (пример из рабочей конфигурации):

```text
UUID=0A4D-CB4F  /mnt/usb-backup  exfat  defaults,nofail  0  2
```

```bash
# Применить fstab без перезагрузки.
sudo systemctl daemon-reload
sudo mount -a

# Проверка: ожидается строка с /mnt/usb-backup размером около 60G.
df -h | grep usb-backup
```

Примечание: exFAT не сохраняет владельцев и права доступа Linux, поэтому бэкап
делается одним архивом tar.gz, а не зеркалом файловой системы через rsync.

### 10.2 Скрипт резервного копирования

Файл `/usr/local/bin/auto-backup.sh` (создать через `sudo nano`):

```bash
#!/bin/bash

BACKUP_DIR="/mnt/usb-backup"
DATE=$(date +%F)
ARCHIVE="$BACKUP_DIR/psybot-$DATE.tar.gz"
LOG_FILE="/var/log/usb-backup.log"

# Проверка монтирования
if ! mountpoint -q "$BACKUP_DIR"; then
    echo "[$(date)] ОШИБКА: Флешка не смонтирована в $BACKUP_DIR" >> "$LOG_FILE"
    exit 1
fi

echo "[$(date)] Начало резервного копирования..." >> "$LOG_FILE"

# Создание архива
tar -czf "$ARCHIVE" \
    --exclude='/proc/*' --exclude='/sys/*' --exclude='/tmp/*' \
    --exclude='/run/*' --exclude='/mnt/*' --exclude='*.log' \
    --exclude='.cache' --exclude='__pycache__' --exclude='node_modules' \
    -C / home/crashkkm etc >> "$LOG_FILE" 2>&1

if [ $? -eq 0 ]; then
    echo "[$(date)] Успешно: $ARCHIVE" >> "$LOG_FILE"
    # Удалить архивы старше 30 дней
    find "$BACKUP_DIR" -name "psybot-*.tar.gz" -mtime +30 -delete
else
    echo "[$(date)] ОШИБКА при создании архива" >> "$LOG_FILE"
fi
```

```bash
# Сделать скрипт исполняемым.
sudo chmod +x /usr/local/bin/auto-backup.sh

# Тестовый запуск и проверка результата.
sudo /usr/local/bin/auto-backup.sh
tail -n 10 /var/log/usb-backup.log
ls -lh /mnt/usb-backup
```

Ожидается: в логе строка "Успешно", в папке флешки архив psybot-ГГГГ-ММ-ДД.tar.gz.

### 10.3 Расписание: раз в неделю

```bash
# Открыть расписание суперпользователя.
sudo crontab -e
```

Добавить строку (воскресенье, 03:00):

```cron
0 3 * * 0 /usr/local/bin/auto-backup.sh
```

Если нужны две копии в неделю (среда и воскресенье): `0 3 * * 3,7 /usr/local/bin/auto-backup.sh`.

### 10.4 Восстановление

```bash
# Проверить целостность архива перед распаковкой: ожидается вывод ok.
gzip -t /mnt/usb-backup/psybot-2026-11-06.tar.gz && echo ok

# Распаковать архив в корень: файлы home и etc будут перезаписаны
# версиями из архива. Выполнять осознанно.
sudo tar -xzf /mnt/usb-backup/psybot-2026-11-06.tar.gz -C /
```

Сценарий полной потери SD-карты: записать свежий образ Raspberry Pi OS на новую
карту, загрузиться, подключить флешку и распаковать архив командой выше -
домашний каталог и конфигурации вернутся в новую систему.

### 10.5 Копия архивов на ПК (раз в месяц)

```bash
# ВЫПОЛНЯЕТСЯ НА ПК: скопировать свежие архивы в локальную папку.
scp crashkkm@192.168.0.103:/mnt/usb-backup/psybot-*.tar.gz ./pi-backups/
```

### 10.6 Локальный снимок перед рискованными изменениями

```bash
# Быстрый архив home и etc на саму SD-карту (дополнение, не замена бэкапа на флешку).
mkdir -p ~/backups
tar -czf ~/backups/pi-$(date +%F).tar.gz \
    --exclude='.cache' --exclude='__pycache__' --exclude='node_modules' \
    --exclude='venv' --exclude='.venv' \
    -C / home/crashkkm etc
```

Когда запускать: вручную перед экспериментами с конфигами и обновлениями.

## 13. Диагностика проблем

### Троттлинг и питание

```bash
vcgencmd get_throttled
```

Расшифровка значения (шестнадцатеричные биты):
- 0x1 - нехватка напряжения сейчас;
- 0x2 - принудительное ограничение частоты сейчас;
- 0x4 - троттлинг по перегреву сейчас;
- 0x10000 - нехватка напряжения случалась ранее;
- 0x20000 - ограничение частоты случалось ранее;
- 0x40000 - троттлинг случался ранее.

Норма - 0x0. При ненулевом значении проверить:
блок питания (нужен оригинальный USB-C 5V/3A), кабель питания,
работу вентилятора, температуру `vcgencmd measure_temp`.

### Закончилось место на диске

```bash
# Найти самые тяжелые папки.
sudo ncdu /

# Проверить размер журнала systemd.
journalctl --disk-usage

# Проверить размер данных Docker.
sudo du -sh /var/lib/docker

# Экстренная очистка (удаляет все неиспользуемое).
docker system prune -af --volumes
sudo journalctl --vacuum-time=1d
sudo apt clean
sudo apt autoremove --purge -y
```

### Флешка не монтируется или бэкап не создается

```bash
# Видит ли система флешку и под каким именем.
lsblk

# Примонтирована ли она в нужную точку.
df -h | grep usb-backup

# Что пишет скрипт бэкапа.
tail -n 20 /var/log/usb-backup.log

# Ошибки ядра по USB-накопителю в текущей загрузке.
dmesg | grep -i sda | tail -n 20
```

Типовые причины и решения:
- Флешку переформатировали - изменился UUID: узнать новый через
  `sudo blkid /dev/sda1`, поправить строку в fstab, затем
  `sudo systemctl daemon-reload && sudo mount -a`.
- В dmesg ошибки вида `Can't find ext4 filesystem` или `bad superblock` после
  форматирования ext4 средствами Pi через порт USB 3.0: известная особенность
  контроллера USB 3.0 Pi 4 (VL805) с рядом флешек - запись молча повреждается.
  Решение: форматировать флешку на ПК (exFAT) либо в порту USB 2.0 (черный);
  не повторять форматирование ext4 на Pi в порту USB 3.0.
- Флешка отсутствовала при загрузке: с опцией nofail в fstab система стартует
  без нее; после подключения выполнить `sudo mount -a`.
- Архив не создается, хотя флешка смонтирована: проверить исполняемый бит
  скрипта (`sudo test -x /usr/local/bin/auto-backup.sh`) и наличие задачи
  в cron (`sudo crontab -l`).

### Прочее

```bash
# Нет графика температуры в Netdata: проверить, что коллектор собирает данные.
# tr заменяет запятые на переводы строк, чтобы JSON читался построчно, grep ищет temp.
curl -s http://127.0.0.1:19999/api/v1/charts | tr ',' '\n' | grep -i temp
sudo systemctl restart netdata

# Контейнер не отвечает извне: проверить статус, проброс портов и firewall.
docker ps
sudo ufw status
```
